# Product_IDを使った仕上表出力 設計

## 目的

Revitモデルに設定された部屋名と層別Product_IDを使い、現在選択中の製品データソースから一般名称を取得して、所定のExcel雛型へ内部仕上表と外部仕上表を出力する。

利用者はBUIドッキングパネルではなく、Revitリボンの独立した「仕上表出力」ボタンから実行する。ドッキングパネルは従来どおり、ID付与と材料検索を主用途とする。

## 成功条件

- Revitの「部屋集計表」にある部屋名を名寄せし、正規化後の部屋名順で内部仕上表を出力できる。
- 壁、床、天井の層別Product_IDを部屋と仕上・下地へ正しく対応付けられる。
- 壁の両面仕上を、内側・外側の部屋名と複合構造の端部レイヤーから区別できる。
- 部屋名を持たない外部要素を、カテゴリ・ファミリ・タイプ単位の外部仕上表へ出力できる。
- 現在選択中のCSVまたはSQL ServerからProduct_IDに対応する一般名称を取得できる。
- 一般名称を解決できない場合もExcelを生成し、影響セルを薄い赤色で示せる。
- Product_IDが空欄のレイヤーは、空気層など製品に対応しない正常な状態として無視できる。
- 元のExcel雛型を変更しない。

## 対象外

- RevitモデルへのProduct_ID書き戻し
- 部屋境界のジオメトリ解析による部屋推定
- 巾木、廻縁の自動取得
- 面積、数量、単価、原価の出力
- 製品名や建材分類を一般名称の代替として自動採用する処理
- Product_IDが空欄のレイヤーに対する警告

## 用語

- **現在選択中の製品データソース**: 設定画面でアドインが現在使用しているCSVフォルダまたはSQL Server。別のGoldStandardファイルを探しに行く意味ではない。
- **一般名称**: `Product_Specs`で`spec_key = general_name`の行にある`value_string`。`Spec_Master`では`general_name`の表示名が「一般名称」と定義される。
- **層スロット**: `Product_ID（仕上）`、`Product_ID（下地①）`から`Product_ID（下地⑤）`までの6項目。
- **内部仕上**: 部屋名パラメータによって部屋へ対応付けられた仕上・下地。
- **外部仕上**: 内部の部屋名に対応しない要素について、カテゴリ・ファミリ・タイプ単位でまとめた仕上・下地。

## 利用者操作

1. RevitリボンのBUIパネルで「仕上表出力」を押す。
2. アドインがアクティブ文書を読み、内部仕上と外部仕上を事前検査する。
3. 確認画面に次を表示する。
   - 内部仕上の部屋数
   - 外部仕上のファミリ・タイプ数
   - 一般名称未登録のProduct_ID数
   - 一般名称未登録の影響を受ける部屋数
   - 一般名称未登録の影響を受ける外部ファミリ・タイプ数
   - その他の警告件数
4. 利用者が保存先を選ぶ。
5. アドイン同梱の固定雛型をコピーしてExcelを生成する。
6. 完了画面に出力先と警告件数を表示する。

既定ファイル名は`<Revitプロジェクト名>_仕上表_<yyyyMMdd>.xlsx`とする。

## データソース

仕上表出力は、BUIパネルが現在使用している製品リポジトリと同じインスタンスを共有する。

### CSV使用時

- `Products.csv`
- `Product_Specs.csv`
- `Spec_Master.csv`

### SQL Server使用時

- `dbo.Products`
- `dbo.Product_Specs`
- `dbo.Spec_Master`

アドインは起動時にCSVから始まり、利用者が設定画面でSQL Serverへ切り替えた後は、その切替済みデータソースを出力でも使用する。出力コマンドが独自に別フォルダのCSVや固定DBを読み直してはならない。

一般名称の解決順序は次のとおりとする。

1. Product_IDを完全一致で製品リポジトリから検索する。
2. 対応する製品の属性から「一般名称」を取得する。
3. Product_IDが製品リポジトリにない場合は未解決とする。
4. 製品はあるが一般名称が空の場合も未解決とする。
5. `product_name`や`category_name_ja`への自動フォールバックはしない。

## Revit入力

### 部屋集計表

Revitの「部屋集計表」に表示される「名前」を、内部仕上表へ出力する部屋の基準一覧とする。部屋名は後述の正規化キーで名寄せする。同じ正規化キーになる部屋は1行へ集約する。

「部屋集計表」または「名前」列を取得できない場合は、内部仕上表の基準を確定できないため処理を停止する。

### 部屋名パラメータ

現時点では次の完全一致名でテキスト値を読む。

- 壁: `st_部屋名（内側）`
- 壁: `st_部屋名（外側）`
- 床・天井: `st_天井・床部屋要素ID`

`st_天井・床部屋要素ID`は名称に「要素ID」を含むが、実際の格納値は部屋名である。床・天井は1要素につき1部屋名を格納する運用とする。

これらの項目に共有パラメータGUIDが将来定義された場合、読取アダプターだけをGUID参照へ差し替えられる境界を設ける。

### Product_IDパラメータ

既存の固定GUIDを使って、次のインスタンスパラメータを読む。

- `Product_ID（仕上）`
- `Product_ID（下地①）`
- `Product_ID（下地②）`
- `Product_ID（下地③）`
- `Product_ID（下地④）`
- `Product_ID（下地⑤）`

Product_IDが空欄のスロットは無視する。警告、赤色表示、備考の対象にしない。

## 部屋名の正規化

部屋名は表示用の原文と、照合・並び替え用の正規化キーを分けて保持する。

正規化は次に限定する。

1. 前後の空白を除去する。
2. 全角スペースを半角スペースへ変換する。
3. 連続する空白を1文字へ統一する。
4. 全角英数字を半角へ変換する。
5. 英字の大文字・小文字を区別しない。
6. 部屋番号、階、棟、その他の記号は削除しない。
7. あいまい一致は行わない。

内部仕上表の行は正規化キーで昇順に並べる。セルAに表示する名称は、部屋集計表の原文を使用する。

## 層の判定

### 共通規則

既存の`CompoundStructureReader`と`LayerSlotMapper`が使う層順を再現し、層スロットの番号だけで仕上・下地を推測しない。各スロットに対応する実際の複合構造レイヤー、その端部位置、Revitのレイヤー機能を併せて判定する。

Product_IDが設定されているレイヤーだけを一般名称解決へ渡す。

### 壁

- `st_部屋名（内側）`がある場合、室内側端の仕上レイヤーを内側部屋の壁仕上とする。
- `st_部屋名（外側）`がある場合、反対側端が`Finish1`または`Finish2`なら、その端に対応する層スロットを外側部屋の壁仕上とする。
- 外側仕上は、壁の総レイヤー数に応じて下地③や下地⑤に格納され得る。最大番号を固定的に外側仕上とはみなさない。
- 外側部屋名が空欄の場合、下地①から最大番号までを内側部屋の下地として扱う。最大番号のProduct_IDを外側仕上へ昇格させない。
- 内側・外側の部屋名が両方空欄の場合、内部仕上表には入れず外部仕上候補とする。

両側に部屋がある場合、それぞれの部屋から見た端部仕上を仕上欄へ入れる。反対側の仕上として採用したレイヤーは、その部屋の下地一覧へ重複して入れない。残りの非空Product_IDレイヤーは、各部屋の面から構造側へ向かう順序で下地候補とする。

### 床・天井

- `st_天井・床部屋要素ID`にある1件の部屋名へ対応付ける。
- 既存カテゴリ規則に従い、床は複合構造の先頭側、天井は末尾側を室内側として扱う。
- 室内側端を仕上、残りの非空Product_IDレイヤーを表面側から構造側の順で下地とする。
- 部屋名が空欄の場合は外部仕上候補とする。

### 屋根と外部仕上

屋根は部屋名を使わず、外部仕上候補とする。壁、床、天井で内部用部屋名を持たない要素も外部仕上候補とする。

外部面の端部はカテゴリ別の`ExteriorSideResolver`で決める。単純に最大番号の下地スロットを採用しない。外部面を一意に確定できない要素は推測せず警告にする。

外部仕上は次のキーで集約する。

1. Revitカテゴリ
2. ファミリ名
3. タイプ名

同じファミリ・タイプには同じProduct_ID一式が設定される運用を前提とする。ただし実データが異なる場合は黙って統合せず、Product_ID構成別に行を分けて警告する。

## 集約規則

### 内部仕上

- 1行は1つの正規化済み部屋名とする。
- 同じ部屋・同じ部位に複数の一般名称がある場合、重複を除いて1セル内に改行して記載する。
- 仕上名称は正規化後の名称で安定ソートする。
- 下地名称は各部屋面からの最小層深度を優先し、同じ深度では正規化後の名称で安定ソートする。
- Product_IDが空欄のレイヤーは集約対象に含めない。

### 外部仕上

- 1行は1つのカテゴリ・ファミリ・タイプとする。
- 同じタイプの要素数を集計する。
- 仕上・下地の一般名称は内部仕上と同じ重複排除、層順、改行規則を使う。

## Excel出力

### 固定雛型

`仕上表_雛型.xlsx`をアドインのリソースとして同梱し、出力時にコピーして必要セルだけをOpen XMLで更新する。Microsoft ExcelのCOM操作は使わない。元の雛型は変更しない。

出力は保存先と同じディレクトリの一時ファイルへ生成し、検証に成功した場合だけ最終ファイル名へ移動する。不完全なファイルを完成品として残さない。

### 内部仕上表

既存の`仕上表`シートを使う。

| 列 | 内容 |
| --- | --- |
| A | 部屋名 |
| B | 床／仕上 |
| C | 床／下地 |
| D | 壁／仕上 |
| E | 壁／下地 |
| F | 巾木（今回は空欄） |
| G | 天井／仕上 |
| H | 天井／下地 |
| I | 廻縁（今回は空欄） |
| J | 備考 |

データは3行目から出力する。雛型の100部屋分を超える場合は、最終入力行の書式、罫線、行高をコピーして必要行数まで拡張する。

### 外部仕上表

同じブックに`外部仕上表`シートを追加する。

| 列 | 内容 |
| --- | --- |
| A | カテゴリ |
| B | ファミリ |
| C | タイプ |
| D | 外側仕上 |
| E | 外側下地 |
| F | 要素数 |
| G | 備考 |

並び順はカテゴリ、ファミリ名、タイプ名の順とする。ヘッダーは内部仕上表と同じ青背景・白文字を使う。

### 一般名称未解決の表示

| Product_ID | 製品 | 一般名称 | 処理 |
| --- | --- | --- | --- |
| 空欄 | ― | ― | 無視。警告・色付けなし |
| あり | あり | あり | 通常出力 |
| あり | あり | なし | 解決できた名称は出力し、該当セル全体を薄い赤色にする |
| あり | なし | ― | 該当セルを薄い赤色にする |

薄い赤色は`#F4CCCC`を使い、既存の罫線、文字、配置は維持する。未解決のProduct_IDは備考へ次の形式で記載する。

- `一般名称未登録: <Product_ID>`
- `Product_ID未登録: <Product_ID>`

同じセルに解決済みと未解決のProduct_IDが混在する場合、解決済み名称は通常どおり表示し、セル全体を薄い赤色にする。

## コンポーネント境界

### Revit依存

- `ExportFinishScheduleCommand`: リボンから呼ばれる読取専用`IExternalCommand`。
- `RevitFinishSourceCollector`: 部屋集計表、対象要素、部屋名パラメータ、複合構造、Product_IDを読み取る。
- `ExteriorSideResolver`: カテゴリごとの外部面を判定する。

### Revit非依存の共有ロジック

- `RoomNameNormalizer`: 表示名と正規化キーを生成する。
- `FinishLayerClassifier`: レイヤー位置・機能・部屋名から仕上と下地を分類する。
- `GeneralNameResolver`: 現在選択中の製品リポジトリから一般名称を解決する。
- `FinishScheduleAggregator`: 内部部屋単位と外部ファミリ・タイプ単位に集約する。
- `FinishScheduleModels`: 入力スナップショット、出力行、警告、セル状態を表す。

### Excelと画面

- `FinishScheduleWorkbookWriter`: 同梱雛型をOpen XMLで編集する。
- `FinishScheduleExportDialog`: 事前検査の件数と警告を表示する。
- 保存先選択サービス: `.xlsx`の保存先と既定ファイル名を扱う。

### 構成

出力機能は、パネルと同じ切替可能な製品リポジトリを共有する。ViewModelの非公開フィールドへ直接依存させず、アプリケーションの構成ルートで出力サービスとViewModelへ同じリポジトリを注入し、セッションからリボンコマンドへ出力サービスを渡す。

## エラー処理

### 処理を停止するエラー

- Revitプロジェクトが開かれていない。
- 「部屋集計表」または「名前」列を読み取れない。
- 必須の部屋名パラメータ定義を読み取れない。
- 同梱雛型がない、または破損している。
- 保存先へ書き込めない。
- Excel生成または最終ファイル検証に失敗した。

### 出力を続行する警告

- 非空Product_IDが現在の製品データソースに存在しない。
- 非空Product_IDの一般名称がない。
- 壁の外側部屋名はあるが、外側仕上を特定できない。
- 7層以上で反対側端が6スロットに収まらない。
- 同じファミリ・タイプで異なるProduct_ID構成がある。
- 部屋集計表にはあるが、仕上要素を1件も取得できない。
- 外部面を一意に判定できない。

Product_IDが空欄のレイヤーは警告に含めない。

## テスト方針

### 自動テスト

- 壁の内側・外側仕上の振り分け
- 外側部屋名が空欄の場合に最大番号側を下地として維持すること
- 外側仕上が下地③または下地⑤に格納されるケース
- 床・天井の1要素・1部屋の振り分け
- 部屋名の全角・半角・空白・英字大小文字の正規化
- 同じ部屋・同じ部位の一般名称の重複排除とセル内改行
- 下地の表面側から構造側への並び
- Product_ID空欄を無視すること
- Product_ID未登録と一般名称未登録を区別すること
- 一般名称未登録セルの`#F4CCCC`表示
- 内部仕上表の正規化部屋名順
- 外部仕上表のカテゴリ・ファミリ・タイプ順
- 100部屋を超えた場合の行拡張と書式継承
- 同じ外部ファミリ・タイプの要素数集計
- 異なるProduct_ID構成を黙って統合しないこと
- 元のExcel雛型を変更しないこと
- CSVとSQL Serverの切替済みリポジトリを共有すること

### Revit実機確認

- 壁を反転したモデル
- 内壁と外壁
- 両面仕上が異なる壁
- 外側部屋名が空欄の壁
- 床・天井
- 屋根と外部仕上
- 7層以上の複合構造
- CSV使用時とSQL Server切替後
- 生成したExcelをMicrosoft Excelで開いたときの書式、セル内改行、行拡張、印刷状態

## 実装上の制約

- Revitモデルを変更しないため、出力コマンドはトランザクションを開始しない。
- UIスレッド上の`IExternalCommand`からRevit APIを読む。モデルレス画面用のExternalEventは使わない。
- Excel COMを使わない。
- 出力処理が独自の製品データソースを作らない。
- 警告対象を自動補正しない。
- 既存の層スロットGUIDと順序を変更しない。
