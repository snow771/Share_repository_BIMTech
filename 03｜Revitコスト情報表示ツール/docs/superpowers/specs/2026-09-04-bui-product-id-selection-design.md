# BUI Product_ID 候補選択・付与機能 設計

**作成日:** 2026-09-04
**対象:** BUI共通基盤PoC（`BUI_Addin_CSharpアドイン`）
**前提仕様:** `docs/superpowers/specs/2026-09-01-bui-common-foundation-poc-design.md`

## 1. 目的

設計者がRevit上で要素を選び、製品データから**候補を絞り込んで選択し、Product_IDを付与する**。既にIDが付いている要素は、同じ手順で選び直して訂正できる。候補に無い製品はその場でCSVへ新規登録して付与できる。

これは設計者の仕様決定を支援する機能であり、既存のpyRevit拡張 `建材・単価情報.extension` のUXを踏襲する。

## 2. 背景と現状

BUIの現状は「Product_IDを手入力 → プレビュー → 実行」で、候補から選ぶ導線が無い。手入力は製品コードの記憶と打ち間違いを利用者に強いる。

既存のpyRevit実装は、カスケードフィルターで候補を絞り、一覧から選び、コードを書き込む流れを持つ。実運用で使われている操作感なので、これを土台にする。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 候補 | 現在の絞り込み条件に合致する製品レコード |
| カスケードフィルター | ある項目を選ぶと、他の項目の選択肢が連動して狭まる絞り込み |
| 対象要素 | Revitで選択中の要素。付与の起点 |
| 同一タイプ | `Element.GetTypeId()` が一致するインスタンスの集合 |

## 4. 決定事項

ブレインストーミングで合意した内容。

| 論点 | 決定 |
|---|---|
| 対象範囲 | 1要素ずつの選定を基本とし、同一タイプへは同じIDを付与できる |
| 新規登録 | 含める |
| 画面配置 | 既存の「検索」タブを拡張する |
| 同一タイプへの適用 | 既定でタイプ全体。件数の内訳を見せて確認を取る |
| 絞り込みの実装 | 共有ロジックの純粋関数で行う（案A） |
| 競合時の確認 | 2回（内訳の確認 → 上書きの確認） |
| CSV追記後にRevit書込が失敗 | 追加した行を削除して元に戻す |

## 5. 全体構成

### 5.1 境界

画面と絞り込みの間に契約を1つ置く。将来のSQL Server移行時、画面とテストを変えずに実装だけ差し替えるため。

```csharp
namespace Bui.Data;

/// <summary>現在の絞り込み条件から、各項目の選択肢と該当候補を返します。</summary>
public interface ICandidateSource
{
    Task<CandidateView> QueryAsync(CandidateQuery query, CancellationToken cancellationToken);
}

/// <summary>選択中の絞り込み条件。空文字は「(すべて)」を表します。</summary>
public sealed record CandidateQuery(
    IReadOnlyDictionary<string, string> Selections,
    string Text,
    int Limit = 200);

/// <summary>絞り込み結果。画面はこれだけを見て表示を組み立てます。</summary>
public sealed record CandidateView(
    IReadOnlyList<CandidateFilterOptions> Filters,
    IReadOnlyList<ProductRecord> Candidates,
    int TotalCount,
    bool IsTruncated);

/// <summary>1つの絞り込み項目と、その時点で選べる値。表示名は列名をそのまま使うため持ちません。</summary>
public sealed record CandidateFilterOptions(
    string Column,
    string Selected,
    IReadOnlyList<string> Values);
```

### 5.2 実装の段階

| 段階 | 実装 | 置き場所 |
|---|---|---|
| PoC（CSV・数百件） | `InMemoryCandidateSource` | `Bui.Shared_共有ロジック/Data_データ窓口/` |
| 次（SQL Server） | `SqlCandidateSource` | 同上。画面は無変更 |

`InMemoryCandidateSource` は `IProductRepository.SearchAsync` で全件を取得し、純粋関数 `ProductCandidateFilter` に渡す。CSVリポジトリは既に全件をキャッシュしているため、追加の読み込みは発生しない。

## 6. 絞り込みの仕様

### 6.1 対象項目

既定は次の6項目。順序も表示順とする。

```
カテゴリー / 用途 / メーカー名 / 製品名 / 型番 / 構造
```

設定ファイルで変更できる。実データの列名に依存するため、既存のCSV列対応と同じ扱いにする。

`Settings.Default_共通設定.json` の `data` に追加する。

```json
"candidateFilterColumns": ["カテゴリー", "用途", "メーカー名", "製品名", "型番", "構造"]
```

CSVに存在しない列名が設定された場合、その項目は選択肢が空になる。エラーにはせず、状態表示に「絞り込み項目『○○』はCSVにありません。」と出す。列が無いだけで機能全体を止めない。

### 6.2 カスケードの定義

**項目Fの選択肢 = 「F以外のすべての絞り込みと文字列検索」を適用した結果に現れる、Fの値の集合。**

自分自身の選択は無視する。これにより、ある項目を選んだあとでもその項目の他の値へ切り替えられる。

- 各項目の先頭に `(すべて)` を置く。これが未選択を表す
- 値は重複を除き、序数比較で昇順に並べる
- 空文字とnullは選択肢に含めない
- 選択中の値が選択肢から消えた場合、その項目は `(すべて)` に戻す

### 6.3 値の突き合わせ

- 前後の空白を除いてから比較する
- 大文字・小文字を区別しない（`OrdinalIgnoreCase`）
- 文字列検索は、対応付け済みの値と追加属性の全体に対する部分一致（既存の `SearchAsync` と同じ規則）

### 6.4 件数の上限

候補一覧は既定200件で打ち切り、`IsTruncated` を立てる。画面は「200件を超えるため一部のみ表示しています。絞り込んでください。」と出す。`TotalCount` は打ち切り前の総数を返す。

## 7. 画面仕様

### 7.1 検索タブの構成

上から順に配置する。

1. **対象要素の表示** … 「対象: 壁『W-01』／現在のProduct_ID: BM-0012」。未選択時は「Revitで要素を選択してください。」
2. **絞り込み** … 6項目のプルダウン、文字列検索欄、「絞り込みを解除」ボタン
3. **候補一覧** … 「製品名 / メーカー名 / 型番」の1行表示。件数を見出しに出す
4. **選択中の製品の詳細** … Product_IDと主要項目
5. **操作** … 「選択要素に付与」「候補が無いので新規登録」
6. **新規登録の折りたたみ領域** … 既定は閉じている

### 7.2 モードを持たない

pyRevit版の参照／選定／再選定／新規登録のモード切替は設けない。

- 参照は「概要」タブが担当する
- 検索タブは常に選定として動く
- **既にProduct_IDが付いた要素を選択した場合、その製品の値で絞り込みを初期化する。** 結果として再選定になる。初期化した旨を状態表示に出す
- そのProduct_IDがCSVに存在しない場合（旧IDや手入力の誤りなど）、絞り込みは初期化せず全件を表示し、「現在のProduct_ID『○○』は製品データにありません。」と状態表示に出す。付与操作自体は通常どおり行える
- 新規登録は折りたたみ領域の開閉で表現する

対象要素が常時表示されるため、利用者が「今どのモードか」を意識する必要がない。

### 7.3 状態表示

検索タブ既存の `StatusMessage` を使う。設定タブの `SettingsStatusMessage` とは分離済み。

## 8. 付与の仕様

### 8.1 流れ

```
候補を選択 → [選択要素に付与] → プレビュー（書き込まない）
  → 内訳を確認 → 実行 → 1トランザクションで書込み
```

既存の `IIdentifierWorkflowService.PreviewProductAsync` / `ApplyAsync` を使う。新しい書込み経路は作らない。プレビューの使い捨てトークンによる整合性確認も既存のまま。

### 8.2 対象範囲

既定で**同一タイプの全インスタンス**。判定は `Element.GetTypeId()` の一致で行う。表示名は言語設定で変わるため使わない。

既存の一括付与（表示中ビュー／プロジェクト全体）は概要タブに残す。検索タブからの付与は同一タイプに限定する。

### 8.3 プレビューの内訳

| 区分 | 意味 | 既定の扱い |
|---|---|---|
| 書き込む | Product_IDが空 | 書き込む |
| 既に同じ | 同じIDが入っている | 変更しない |
| 別のIDあり | 異なるIDが入っている | **既定では書き込まない**。上書きは2回目の確認で明示的に選ぶ |
| 書き込めない | パラメータ無し・読取専用・リンク要素 | 書き込まない。理由を要素IDとともに表示 |

### 8.4 確認

1回目は内訳の確認。「別のIDあり」が1件以上ある場合のみ、2回目に「別のIDが入っている○件を上書きしますか」を出す。2回目に同意しない場合、競合分を除いて実行する。

### 8.5 書き込み

- 1つの `TransactionGroup` と1つのトランザクションにまとめる。**Ctrl+Z 1回**で一括して戻る
- 失敗した要素は要素IDと理由を一覧で返す
- Product_IDの「不変・再利用禁止」は、**IDの値を別製品へ使い回さない**という意味である。要素への割り当ての訂正は想定内であり、確認付きで許可する

## 9. 新規登録の仕様

### 9.1 入力項目

pyRevit版と同じ8項目。`*` は必須。

```
カテゴリー* / 用途 / メーカー名* / 製品名* / 型番 / 構造 / 製品画像 / 商品コード
```

設定ファイルで変更できる。既定値は上記。

### 9.2 重複候補の検出

次の6項目で既存レコードと比較し、候補を提示する。

```
カテゴリー / 用途 / メーカー名 / 製品名 / 型番 / 構造
```

- 入力が空の項目は比較に含めない
- 比較は前後空白を除き、大文字小文字を区別しない
- 一致した項目数の多い順に、最大20件を提示する
- **重複があっても登録は止めない。** 判断は利用者に委ねる。状態表示で注意を促す

### 9.3 採番

`BM_NEW-0001` 形式。既存の同形式コードのうち最大の番号 + 1。

- 既存の `AssemblyIdAllocator` と同じ考え方で `ProductIdAllocator` を作る
- 形式に合致しない既存コード（`BM-0012` など）は無視する
- 接頭辞と桁数は設定で変更できる。既定は `BM_NEW-` と 4桁
- 桁が溢れる場合は登録を拒否し、「採番の上限に達しました。」と表示する

### 9.4 書き込みと補償

```
1. CSVへ追記（書込前バックアップ + 一時ファイル経由の置換 + 競合検出）
2. 成功したら、そのIDで付与のプレビューへ
3. 付与に失敗した場合、追加した行を削除して元に戻す
```

補償は `ProductRegistrationCoordinator` が担う。Assembly_IDで使っている `AssemblyPersistenceCoordinator` と同じ考え方。CSVだけに幽霊レコードが残る状態を作らない。

補償自体が失敗した場合は、**元の例外と補償の失敗の両方**を利用者に伝え、ログへ残す。追加された行のIDを明示し、手作業で確認できるようにする。

### 9.5 事前確認

CSVが読み取り専用・使用中の場合、**入力を始める前に**検出して案内する。入力させてから失敗させない。

## 10. エラー処理

| 状況 | 振る舞い |
|---|---|
| 要素未選択 | 付与ボタンを無効化。理由を表示 |
| 候補未選択 | 同上 |
| 対象0件 | 実行ボタンを無効化。「書き込む対象がありません。」 |
| CSVが読めない | 候補一覧を空にし、理由を表示（既存の `DataProblemsText` と同じ規則で、保存場所は表示しない） |
| CSVが書けない | 新規登録を開始させない |
| 絞り込み項目がCSVに無い | その項目だけ空にし、状態表示で知らせる。機能は止めない |
| Revit書込中の例外 | 既存の `ErrorBoundary` を通し、日本語の利用者向け文言と技術詳細の分離を維持する |

## 11. 設定

`Settings.Default_共通設定.json` の `data` に追加する。

```json
"candidateFilterColumns": ["カテゴリー", "用途", "メーカー名", "製品名", "型番", "構造"],
"newProductColumns": ["カテゴリー", "用途", "メーカー名", "製品名", "型番", "構造", "製品画像", "商品コード"],
"newProductRequiredColumns": ["カテゴリー", "メーカー名", "製品名"],
"duplicateCompareColumns": ["カテゴリー", "用途", "メーカー名", "製品名", "型番", "構造"],
"newProductIdPrefix": "BM_NEW-",
"newProductIdDigits": 4
```

既存の出荷設定を検証しているテスト（`ShippedDefaults_合意済みの構造と値に一致する`）の期待値も同時に更新する。

## 12. テスト

### 12.1 単体テスト（私用PCで実行可能・Revit不要）

**`ProductCandidateFilter`**

- 未選択ならすべての値が選択肢に出る
- 1項目を選ぶと、他項目の選択肢がその条件で狭まる
- **自分自身の選択は自分の選択肢に影響しない**（他の値へ切り替えられる）
- 選択値が候補から消えたら `(すべて)` に戻る
- 前後空白・大文字小文字を無視して突き合わせる
- 空文字とnullは選択肢に含まれない
- 文字列検索と併用できる
- 200件を超えると打ち切り、`TotalCount` は総数を返す
- CSVに無い列を指定しても例外にならず、選択肢が空になる

**`ProductIdAllocator`**

- 空の集合から `BM_NEW-0001`
- `BM_NEW-0009` の次は `BM_NEW-0010`
- 形式の違う既存コードは無視する
- 接頭辞と桁数を設定で変えられる
- 桁が溢れる場合は失敗を返す

**`ProductDuplicateFinder`**

- 全項目一致を最上位に出す
- 一部一致を一致数の多い順に並べる
- 入力が空の項目は比較に含めない
- 最大20件で打ち切る

**`ProductRegistrationCoordinator`**

- 付与が失敗したら追加行を削除して元に戻す
- 補償も失敗した場合、元の失敗と補償の失敗の両方を返す

**ViewModel**

- 要素未選択・候補未選択で付与コマンドが無効
- 既にIDが付いた要素を選ぶと、その製品の値で絞り込みが初期化される
- 絞り込みを解除すると全件に戻る
- CSVが読めないとき、候補一覧が空になり理由が出る

### 12.2 実機確認（会社PC・`TestChecklist_Revit実機確認.md` に追加）

- 候補を選んで付与し、**Ctrl+Z 1回**で全部戻ること
- 同一タイプの列挙が正しいこと（件数がRevitの選択と一致）
- 既にIDが付いた要素で絞り込みが初期化されること
- 競合がある場合に確認が2回出ること、同意しない場合に競合分が除かれること
- 新規登録して付与できること（**複製CSVで実施すること**）
- 新規登録後にRevit書込を失敗させ、CSVの行が消えること
- プロジェクト全体規模での応答
