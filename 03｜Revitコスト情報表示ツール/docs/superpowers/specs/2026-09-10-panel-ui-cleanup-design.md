# パネル表示の整理 — 設計

日付: 2026-09-10
対象: BUI Revit 2025アドイン（`BUI_Addin_CSharpアドイン`）
出典: `BUI_Addin_CSharpアドイン/UI修正内容.pdf`（利用者による赤入れ、全4ページ）

## 1. 何を直すか

利用者から4点の指摘があった。いずれも**表示だけ**の問題で、データの読み書きは変えない。

| # | 添付 | 指摘 |
| --- | --- | --- |
| ① | P1 | ID初期設定の結果ウィンドウが画面いっぱいに広い |
| ② | P2 | リボンの文字が詰まっている。区切り線とアイコンが欲しい |
| ③ | P3 | 概要タブ: 小数点以下が長い。不要な行が多い。「順序 0」が読みにくい |
| ④ | P4 | 検索タブ: 「現在のProduct_ID」の長い行が不要 |

確認済みの決定事項。

| 論点 | 決定 |
| --- | --- |
| リボンのボタン名 | **パネル表示 / パラメータ作成 / AI** |
| 小数点以下 | **末尾の0を落とす**（`100.0000000000` → `100`） |
| 「レイヤーN」表記 | **概要タブと検索タブの両方**に適用 |

## 2. どこに実装を置くか

**整形の判断は `Bui.Shared`（Revit非依存）へ置き、XAMLとリボンには「どれを出すか」だけを残す。**

私物PCには Revit が無く、`Bui.Addin` はコンパイルすらできない。
テストで固められる範囲を最大にしないと、4点すべてが会社PCでの目視確認頼みになる。

```
Bui.Shared（テストできる）          Bui.Addin（目視確認のみ）
  折り返し計算                  →   TaskDialogのExpandedContent
  末尾0の除去                   →   概要タブの製品カード
  「レイヤーN」の文字列          →   概要・検索タブのXAML
                                    リボンの名前・区切り線・アイコン
```

## 3. ① ID初期設定ダイアログの幅

### 3.1 原因

本文は短いのに横幅が画面いっぱいになるのは、**折りたたまれている「詳細の表示(D)」の中身が原因**である。
`ExpandedContent` にカテゴリ1件＝1行で874件分が入っており、長い行がある。

Revitの `TaskDialog` は**折りたたみ部分も含めて**いちばん長い行に幅を合わせる。
幅を指定するAPIは無い。

### 3.2 対策

**詳細テキストを一定の表示幅で折り返す。**行を削らず折り返すので、情報は1文字も失わない。

幅は**60表示桁**とする（全角2桁・半角1桁で数える）。
本文のいちばん長い行「Product_IDとAssembly_IDの初期設定が完了しました。」が49桁で、
ダイアログの余白とアイコンの幅を考えると、これとほぼ同じ見た目になる。

```csharp
public static class DisplayWidthWrapper
{
    public const int DefaultColumns = 60;
    public static string Wrap(string? text, int columns = DefaultColumns);
}
```

折り返しの規則。

1. 改行はそのまま保つ（1行ずつ独立して折り返す）
2. 1行が上限を超えたら、上限に収まる位置で切って次の行へ送る
3. 折り返した続きの行は**2桁ぶん字下げ**する。字下げが無いと、
   1件が2行に割れたのか2件並んでいるのか読み手に判別できない
4. 全角1文字が境界をまたぐ場合は、その文字ごと次の行へ送る（半端に切らない）

日本語は単語の切れ目が無いため、単語単位の折り返しはしない。文字単位で切る。

### 3.3 表示幅の数え方

`char` 数ではなく**表示桁**で数える。`ID` は2桁、`カテゴリ` は8桁である。
`char` 数で切ると、日本語だけの行が半分の幅にしかならない。

全角として扱う範囲は、East Asian Width の Wide / Fullwidth に相当する主要ブロックとする。
CJK統合漢字、ひらがな、カタカナ、全角記号、CJK記号。それ以外は1桁とする。

サロゲートペア（絵文字など）は2桁として数える。カテゴリ名に現れることは無いが、
数え漏らすと折り返し位置がずれるため、`char` 単位ではなくテキスト要素単位で走査する。

## 4. ② リボン

### 4.1 変えるもの

| いま | これから |
| --- | --- |
| BUIパネル | パネル表示 |
| ID初期設定 | パラメータ作成 |
| AIに聞く | AI |

ボタンの間に区切り線を2本入れる（`RibbonPanel.AddSeparator`）。

アイコンは利用者提供の3点を使う。いずれも32×32が1枚だけの `.ico` で、
Revitの大ボタン用サイズちょうどである。

取り込むときに名前を変える（§4.3）。

| ボタン | もらったファイル | 取り込み後 |
| --- | --- | --- |
| パネル表示 | `imgdiet/01｜パネル表示.ico` | `リボン_01_パネル表示.ico` |
| パラメータ作成 | `imgdiet/02｜初期設定.ico` | `リボン_02_パラメータ作成.ico` |
| AI | `imgdiet/03｜AI確認.ico` | `リボン_03_AI.ico` |

### 4.2 「文字間隔を広げる」について

**文字間隔を直接指定するAPIは無い。**
いま詰まって見えるのは、アイコンが無いためボタンが小文字幅のまま並んでいるからである。
`LargeImage` を設定するとボタンが大ボタン形式になり、添付P2の間隔になる。
**アイコン設置が間隔の対策そのもの**である。

Revitは文字をアイコンの**下**に置く。P2の「文字が上」の配置にはできない。

### 4.3 アイコンの置き場と配置

`Bui.Addin/Resources_画像と定義/` へ取り込む。既存の `BUI.addin` や
`SharedParameters_共有パラメータ.txt` と同じ扱いで、`CopyToOutputDirectory` で出力へ運ぶ。

ファイル名から `｜`（全角縦線）を落とし、ボタン名に合わせた名前へ変える（§4.1の表）。
全角縦線はファイル名として合法だが、配置スクリプトの照合や診断の出力で読みにくい。
`imgdiet` フォルダは受け取り置き場のまま残し、取り込んだ複製を使う。

**`DeployDev_開発用配置.ps1` の許可リストにも追加する。**
このスクリプトは許可リスト方式なので、追加を忘れるとアイコンだけ会社PCに届かない。
届かなかったときの症状は「アイコンが出ない」だけで、原因に辿り着けない。

`LargeImage`（32×32）と `Image`（16×16へ縮小）の両方を設定する。
`Image` を設定しないと、リボンが縮んだ状態でアイコンが消える。

### 4.4 アイコンを読めなかったとき

**読めなくてもボタンは作る。**アイコンの読み込み失敗でリボン作成が落ちると、
BUIのボタンが1つも出ず、利用者にはアドインが壊れたようにしか見えない。
読めなかった場合はアイコン無しのボタンとして作り、そのことを起動ログへ残す。

## 5. ③ 概要タブ

### 5.1 数値の末尾の0

`SpecValueFormatter.FormatNumber` は元データの小数桁数をそのまま保つ。
CSVでは `100.0` だったが、SQL Serverの列は小数10桁のため `100.0000000000` になる。

**末尾の0を落とす。**小数部が空になったら小数点も落とす。

| 元の値 | 表示 |
| --- | --- |
| `100.0000000000` | `100` |
| `2800.0000000000` | `2,800` |
| `0.2200000000` | `0.22` |
| `2.5000000000` | `2.5` |
| `0.22` | `0.22` |
| `8.1～11.7` | `8.1～11.7`（数値として読めない値はそのまま） |

桁区切りは今までどおり付ける。
**丸めは行わない。**`0.225` を `0.23` にすると別の値になる。落とすのは末尾の0だけである。

### 5.2 消す行

| 消すもの | なぜ消してよいか |
| --- | --- |
| `Product_ID: Product_ID（仕上）: … / 下地①: 未設定 / …` | 同じ内容が複合レイヤーの表に層ごとに出ている |
| `CSV接続: …` | 【設定】タブに同じものが出ている |
| `CSV更新: …` | 同上 |
| `CSV詳細: …` | 同上 |
| `状態: …` | 【検索】タブに同じ `StatusMessage` が出ている |

`Assembly_ID` は残す。ここにしか無い。

**この案件は「失敗の理由を必ず画面に出す」を守ってきた。**
消す5行が他のタブに残っていることを確かめた上で消す。
概要タブは確認専用のタブであり、操作をしないので、操作の結果を出す必要が無い。

### 5.3 「順序 0」

`レイヤー1` にする。0始まりを1始まりにする。

```csharp
// CompoundLayerViewModel（概要タブ）と LayerAssignmentRow（検索タブ）の両方に置く
public string LayerLabel => $"レイヤー{Order + 1}";
```

`Order` そのものは変えない。Revitの層の添字であり、共有パラメータの箱の番号と対応している。
**表示だけ1始まりにする。**内部の番号まで1始まりにすると、書き込み先がずれる。

## 6. ④ 検索タブ

| 対象 | どうする |
| --- | --- |
| `現在のProduct_ID: …` の行 | 消す |
| 「層への割り当て」の `順序 0` | `レイヤー1`（③と同じ `LayerLabel`） |
| `現在: ALC-AK-05 → ALC-AK-05` の行 | **残す**。これから書き込む内容の確認に要る |

## 7. 対象外

**【検索】タブの厚さの選択肢に出る `2.5000000000`。**

同じ症状だが直し方が違う。選択肢の文字列は表示だけでなく**絞り込みの照合にも使われている**ため、
表示だけ変えると検索が0件になる。安全に直すには保存値の正規化が要る。別途行う。

その他の対象外。

- リボンの文字をアイコンの上に置くこと（Revitが対応していない）
- `TaskDialog` をWPFウィンドウへ置き換えること（折り返しで足りる）
- 概要タブのレイアウト変更（行を消すだけ）

## 8. 異常時の扱い

| 状況 | 動作 |
| --- | --- |
| アイコンを読めない | アイコン無しでボタンを作る。リボン作成は続行する |
| 折り返し対象が空文字 | 空文字を返す。ダイアログの詳細欄が空になるだけ |
| 折り返し幅に0以下が渡された | 折り返さずそのまま返す（無限ループを作らない） |
| 数値として読めない属性値 | そのまま表示する（`8.1～11.7` を壊さない） |

## 9. 検証

`Bui.Shared` に入る部分は単体テストで確認できる。

1. 表示幅の数え方（半角のみ／全角のみ／混在／サロゲートペア）
2. 折り返しが上限を超えないこと
3. 折り返した続きの行が字下げされること
4. 改行が保たれること
5. 折り返し幅に0以下を渡しても落ちないこと
6. 末尾の0が落ちること（`100.0000000000` → `100`）
7. 有効な小数が残ること（`0.2200000000` → `0.22`）
8. 数値として読めない値がそのまま返ること（`8.1～11.7`）
9. 桁区切りが残ること（`2800.0000000000` → `2,800`）
10. `LayerLabel` が1始まりになること（概要・検索の両方）

**Revitが必要で、こちらでは確認できないもの**（会社PCでの確認事項）。

- ID初期設定ダイアログの横幅が本文の幅に収まること
- リボンに3つのアイコンと2本の区切り線が出ること
- ボタン名が パネル表示 / パラメータ作成 / AI になっていること
- 概要タブから5行が消え、数値が `100 mm` になっていること
- 概要・検索タブの層が `レイヤー1` から始まること
- アイコンが配置先フォルダへ届いていること（`CheckDeploy_配置診断.ps1`）
