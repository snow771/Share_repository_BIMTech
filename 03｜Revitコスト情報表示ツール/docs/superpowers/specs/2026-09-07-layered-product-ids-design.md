# 複層対応のProduct_IDとAssembly_ID — 設計

日付: 2026-09-07
対象: BUI Revit 2025アドイン（`BUI_Addin_CSharpアドイン`）

## 1. 何を作るか

利用者の指示は次のとおり。

| # | 内容 |
| --- | --- |
| ①-1 | 概要タブからID付与を外し、**確認専用**にする |
| ①-2 | 検索タブが**検索・比較・ID登録**を担う |
| ①-3 | 検索タブで**複合レイヤーの各層へ**ID付与できるようにする |
| ①-4 | **同一タイプすべて**へ付けるか**選択部材のみ**かを選べるようにする |
| ②-1 | Product_IDを6つに分ける（仕上／下地①〜⑤） |
| ②-2 | 層IDのまとまりを**Assembly_IDとして自動採番**し、専用パラメータへ入れる |
| — | 両方とも **ID初期設定** で作成できること |

確認済みの決定事項。

| 論点 | 決定 |
| --- | --- |
| 付与先 | 6つのProduct_IDは**要素ごと（Instance）**。Assembly_IDは**タイプ（Type）** |
| 「仕上」の位置 | **室内側の層** |
| 層が7つ以上 | **6層目まで付与し、残りは付与せず警告** |
| 既存Product_ID | **廃止し、6つに一本化** |

## 2. 共有パラメータ

6つのProduct_IDは **Instance** バインド。GUIDは**一度決めたら二度と変えない**。
変えると、既にIDを書き込んだモデルとの互換が失われる。

| パラメータ名 | GUID | 用途 |
| --- | --- | --- |
| `Product_ID（仕上）` | `e10c429c-9ee1-4813-9e59-9178991af83a` | 室内側の層 |
| `Product_ID（下地①）` | `3fcefbeb-ddcc-4f74-bd90-d8be05baf555` | 仕上の1つ外側 |
| `Product_ID（下地②）` | `ba9206e7-d7b1-47aa-894f-1eb71ceb4c53` | 2つ外側 |
| `Product_ID（下地③）` | `0cef352d-edbb-441c-9bd8-43ecf239eb4d` | 3つ外側 |
| `Product_ID（下地④）` | `5b008bd1-2630-4295-ab09-f7cf4cdbf764` | 4つ外側 |
| `Product_ID（下地⑤）` | `79b24248-89df-460d-bbcc-95af64515a63` | 5つ外側 |

`Assembly_ID` は例外で、**Typeバインドのまま**変更しない。

| パラメータ名 | GUID | バインド | 用途 |
| --- | --- | --- | --- |
| `Assembly_ID` | `883267b2-8771-498a-a77e-a698e06b3453`（既存） | **Type** | 層IDのまとまりの識別子 |

複合構造はタイプが持つ情報なので、その識別子もタイプに付くのが自然である。
既存の登録をそのまま使うため、バインド種別の入れ替えは発生せず、
値が失われる心配もない。

### 2.1 既存 `Product_ID`（`569e8df1-…`）の扱い

**新しい書き込みには使わない。ただしモデルからは削除しない。**

削除は利用者のデータを消す操作であり、取り消せない。既に170件書き込まれている。
ID初期設定は既存の `Product_ID` に触れず、6つの新パラメータだけを追加する。
古い値はモデルに残るが、BUIは読まない。付け直しが必要である旨を画面と手順書に書く。

## 3. 層とパラメータの対応

**「仕上」は室内側の層。**そこから外側へ向かって 下地①→⑤ の順に割り当てる。

Revitの複合構造の層順は、カテゴリによってどちら端が室内側かが変わる。

| ホスト | 層順の先頭 | 室内側 |
| --- | --- | --- |
| 壁 | 外部側 | **最後の層** |
| 床 | 上面 | **最初の層** |
| 天井 | 上面 | **最後の層** |
| 屋根 | 上面 | **最後の層** |

割り当ては純粋関数 `LayerSlotMapper`（`Bui.Shared`）が行い、
「どちら端が室内側か」だけをRevit側から受け取る。これで単体テストできる。

**この対応は私の環境では検証できない**（Revitが無い）。誤りが起きても
気づけないため、**付与する前に画面で対応を必ず見せる**。

```
順序5  せっこうボード 12.5mm  → Product_ID（仕上）      BD-YOSHINO-01
順序4  軽量鉄骨下地   45mm    → Product_ID（下地①）     （未選択）
順序0  ALCパネル      100mm   → Product_ID（下地②）     ALC-AK-01
```

利用者はこの表を見て、対応が意図と違えば付与前に気づける。

層が7つ以上ある場合は、室内側から6層目までを割り当て、残りは
「7層目以降には付与しません」と画面に出す。作業は止めない。

## 4. Assembly_ID の採番

**層に入れたProduct_IDの並びが、そのまま構成の識別子になる。**

- 同じ並び → 同じ Assembly_ID
- 並びが違う（順序も含む） → 別の Assembly_ID を採番

既存の `AssemblyIdAllocator` / `AssemblyRecord` / 構成CSV をそのまま使う。
変えるのは**照合のもと**だけで、いまは複合構造の形（層の機能・厚さ・材料）から
指紋を作っている。これを**層のProduct_IDの並び**から作るよう差し替える。

空欄の層がある場合は採番しない。まとまりとして確定していないため、
中途半端な構成に番号を振ると、後から埋めたときに別番号になってしまう。

### 4.1 層IDは要素ごと、Assembly_IDはタイプごと

この2つは付き先が違うため、食い違いが起こり得る。

同じタイプの要素AとBがあり、Aだけに層IDを付けた場合、
タイプのAssembly_IDを書くとBの実態と合わない。BはIDが空のままだからである。

そこで **Assembly_IDは、そのタイプの要素すべてで層IDが揃っているときだけ書く**。
揃っていなければ採番も書き込みもせず、画面にこう出す。

> 同一タイプ内でProduct_IDが揃っていないため、Assembly_IDは付けませんでした。
> 対象範囲を「同一タイプすべて」にして付け直すと採番されます。

これは付与そのものを止める理由にはしない。層IDの書き込みは行い、
Assembly_IDだけを見送る。

## 5. 画面

### 5.1 検索タブ（ID登録の場所）

上から順に。

1. 対象要素の表示（現状のまま）
2. **付与範囲**の選択 … 「同一タイプすべて」／「選択部材のみ」（①-4）
3. 絞り込み（現状のまま）
4. 候補一覧（現状のまま）
5. **層の割り当て表**（新規） … 層ごとに「対応するパラメータ」と「現在のID」を並べ、
   候補一覧で選んだ製品を、選んだ行へ入れる
6. 手順1（内容を確認）→ 手順2（Revitへ書き込む）

単層の要素では、層の表は1行（仕上）だけになる。

### 5.2 概要タブ（確認専用）

**ID付与に関する操作をすべて外す。**残すのは表示だけ。

- 製品カード（現状のまま）
- 選択要素の情報（現状のまま）
- 複合レイヤー一覧 … **表示のみ**。層ごとの製品名とProduct_IDを見せる
- CSV接続状態（現状のまま）

外すもの: 付与するProduct_IDの入力、候補プルダウン、対象範囲、
同一タイプ限定、各プレビューボタン、書き込みボタン、プレビューのリセット。

## 6. 付与範囲（①-4）

| 選択 | 対象 |
| --- | --- |
| 同一タイプすべて | プロジェクト全体にある、選択要素と同じタイプの要素すべて |
| 選択部材のみ | Revitで選択中の要素だけ |

既定は**同一タイプすべて**。設計上そちらが本来の使い方であり、
1件だけ付けたい場合に切り替える。

「選択部材のみ」を選ぶと、同一タイプ内でIDが揃わなくなる可能性がある。
その場合はAssembly_IDが付かない（4.1）。画面でその旨を伝える。

## 7. 影響する既存機能

| 機能 | 対応 |
| --- | --- |
| ID点検（点検タブ） | 6つのパラメータを見るよう変更。未設定の層を報告する |
| 材料へのProduct_ID付与 | **廃止**。層への付与に置き換わる |
| 旧新ID対応CSV | そのまま（層ごとに解決する） |
| 単価連携 | 対象外（保留のまま） |

## 8. 異常時の扱い

| 状況 | 動作 |
| --- | --- |
| 共有パラメータが未登録 | 「ID初期設定を実行してください」と理由付きで出す（実装済みの仕組みを使う） |
| 層が7つ以上 | 6層目まで付与し、残りを画面で知らせる |
| 層のIDが一部だけ空欄 | 付与はする。Assembly_IDは採番しない |
| 同一タイプ内でIDが揃っていない | 層IDは書く。Assembly_IDは書かず、理由を画面に出す |
| 複合構造を持たない要素 | 仕上の1つだけを扱う |
| 書き込み失敗 | 理由をそのまま画面へ出す（実装済み） |

## 9. 検証

`Bui.Shared` に入る部分は単体テストで確認できる。

1. 層数ごとの割り当て（1層・3層・6層・7層以上）
2. 室内側がどちら端かで割り当てが反転すること
3. 7層以上で警告が出て、6層目までは割り当てられること
4. 同じProduct_IDの並びが同じAssembly_IDになること
5. 並び順が違えば別のAssembly_IDになること
6. 空欄がある場合にAssembly_IDを採番しないこと
7. 同一タイプ内でIDが揃っていない場合にAssembly_IDを採番しないこと
8. 付与範囲の選択が、対象の集め方に正しく渡ること

**Revitが必要で、こちらでは確認できないもの**（会社PCでの確認事項）。

- ID初期設定で6つの新パラメータが作られること（Assembly_IDは既存のまま）
- Assembly_IDがタイププロパティ側に出ること
- 層とパラメータの対応が、実際のモデルで意図どおりか
- 各パラメータに値が入ること、Ctrl+Z 1回で戻ること

## 10. 対象外

- 既存 `Product_ID`（170件）の自動移行。付け直しとする
- 単価情報との連携
- 下地⑥以降の追加
