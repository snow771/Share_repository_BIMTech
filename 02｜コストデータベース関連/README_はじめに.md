# 類似物件・実績検索ツール（C# / WPF + WebView2 版）

`similarity_search_desktop_v14.py`（Tkinter 版）を C# のデスクトップアプリに移植したものです。
画面は Amazon 風の3カラム（左: 絞込 / 中央: 上段に単価パネル（2段2列）と分布図、下段に物件一覧 / 右: AIアシスタント）です。物件をクリックすると詳細はモーダルで開きます。

- 設計書: `../docs/superpowers/specs/2026-10-07-similarity-search-csharp-design.md`
- 実装計画: `../docs/superpowers/plans/2026-10-07-similarity-search-csharp.md`

## 必要なもの

| もの | 備考 |
|---|---|
| .NET 8 SDK | `dotnet --list-sdks` で 8.x が出ること（Visual Studio 2022 の「.NET デスクトップ開発」でも可） |
| WebView2 ランタイム | Windows 10/11 には通常インストール済み |
| SQL Server への接続 | Windows 認証 または SQL Server 認証 |
| Ollama（任意） | AI 条件設定を使う場合のみ。既定 `http://127.0.0.1:11434` |

## ビルド・実行・テスト

```bash
cd SimilaritySearchApp
dotnet build
dotnet run --project src/SimilaritySearchApp
dotnet test
```

Visual Studio の場合は `SimilaritySearchApp.sln` を開き、`SimilaritySearchApp` をスタートアッププロジェクトにして F5 を押します。

## 初回の設定

1. 起動したら右上の「⚙ 設定」を開く
2. **DB接続** タブ: サーバー名・DB名・認証方式を入れて「🔌 接続テスト」→「保存」
3. **ローカルLLM** タブ: ベースURLを入れて「⟳ 一覧を取得」→ モデルを選んで「保存」
4. ヘッダーで構造種別（RC造 / S造）を選び、「⚡ データ読込」

設定は `%AppData%\SimilaritySearchApp\settings.json` に保存されます。
SQL 認証のパスワードは Windows の DPAPI で暗号化しているため、別のユーザー・別のPCでは復号できません（その場合は再入力してください）。

想定外のエラーは `%AppData%\SimilaritySearchApp\error.log` に詳細（発生場所）付きで記録されます。不具合の連絡の際はこのファイルを添えてください。

## 該当物件一覧の列幅

見出しの境界（列の右端）をドラッグすると列幅を変えられ、ダブルクリックすると中身に合わせて自動調整します（Excel と同じ）。幅は次回起動時にも引き継がれます。

## 【標準単価】タブ（建築材料マスタ）

中央カラム上部のタブで【単価分析】と【標準単価】を切り替えます。標準単価は `MaterialMaster_建築材料マスタ`（Excel「建築材料マスタ」をDBに登録したもの）から読み込みます。

- **表示範囲:** 工種・工事項目・項目で絞ると、その条件に合う実績明細の工種コード（Work_Type_Code）の標準材料だけを表示します。
  物件を選ぶと、さらに「その物件の実績明細にある工種コード」との共通部分に絞ります。
- **工種コードごとの表示:** 標準の査定単価・修正単価（円/単位）に加えて、選択物件の査定・修正の実績額（円・円/㎡）と、絞込後の物件群での修正単価の中央値（円/㎡）を並べます。
  単位が違うため、比較は目安です。差額単価を含む材料（鉄筋など）もあります。
- **単価の表示:** 0 と未設定（---）を区別して表示します。確認状態が「確認済」以外の行には印が付きます。
- **テーブル名:** 設定 → DB接続 → テーブル名 →「建築材料マスタ（標準単価）」で変更できます。
  列名は `Material_Code` / `Material_Code_建材コード` / `建材コード` のどれでも読めます。
- **読込失敗時:** このテーブルが読めなくても、ほかの機能はそのまま使えます（読込時に警告を表示します）。
- **手動確認:** 内装工事で絞る → 物件を選ぶ → 【標準単価】で、その物件の内装系の工種コードだけが出ることを確認してください。

## DB編集（ヘッダーの「🗄 DB編集」）

ヘッダーの「🔍 検索・分析 / 🗄 DB編集」で画面を切り替えます。標準建材・物件諸条件などのテーブルを、Excel に近い操作で直接修正できます。

1. 左の一覧からテーブルを選ぶ（「このアプリで使用中」が上にまとまっています）
2. 上段の表で編集し、「💾 保存」（Ctrl+S）
3. 下段の**関連テーブル**図で、つながっているテーブルを確認する
   - カードをクリックするとそのテーブルに移動します。カードはドラッグで自由に配置し直せます（線も追従）
   - 背景のドラッグで全体を移動、マウスホイールで拡大縮小、背景のダブルクリックか「⤢ 全体表示」で全体が収まる表示に戻ります
   - 実線: DB の外部キー制約 ／ 点線: 同名のキー列（`Work_Type_Code`、`Project_id` など）からの推定
   - 初期配置は左に親（参照先のマスタ）、右に子（参照元）。「↺ 配置を戻す」で初期配置に戻ります

| 操作 | やり方 |
|---|---|
| 選択 | クリック、ドラッグ・Shift+クリックで範囲、行番号のクリックで行全体 |
| 入力 | そのまま打つと上書き、F2 かダブルクリックで追記編集、Enter で↓、Tab で→、Esc で取消。編集中のセルは黄色地＋オレンジ枠になり、上に「✏ 編集中」と表示されます |
| 表内検索 | 検索欄に入力して **Enter** で検索（入力の途中では検索しません）。× で解除 |
| 空欄の注意 | * の付いた列（必須）が空欄のセルは薄い赤、任意の列の空欄は薄い紫（読込済みの行も含む）。追加・変更した行に必須の空欄があれば保存前の確認で件数を表示します |
| 列幅 | 見出しの境界をドラッグで変更、ダブルクリックで中身に合わせて自動調整（テーブルごとに記憶） |
| 消去 | Delete / Backspace（空欄で保存すると NULL） |
| Excel との受け渡し | Ctrl+C / Ctrl+V（範囲ごと。行が足りなければ自動で追加） |
| 行の追加・削除 | 「＋ 行を追加」/「－ 行を削除」（削除予定の行をもう一度押すと取消） |
| 元に戻す | Ctrl+Z または「↶ 元に戻す」 |

- **保存の安全策:**
  - 保存するまで DB には反映されません。変更したセルは黄、追加行は緑、削除予定の行は赤で表示します。
  - 保存は1トランザクションで、1件でも失敗したらすべて取り消します。主キー重複・外部キー違反・必須列が空などの理由は日本語で表示します。
  - 主キーの無いテーブルは、読込時の全列の値で行を特定します。同じ内容の行が複数ある場合と、他の人が先に変更していた場合は保存しません。
- **物件の削除:** 物件情報（設定の物件情報テーブル）の行を削除すると、同じ project_id を持つ他のテーブル（査定単価・修正単価など、project_id 列のあるテーブルすべて）の行も同じトランザクションで先に削除します。保存前の確認に、どのテーブルから何行消えるかを表示します。さらにその行を参照しているテーブルがある場合（OCR 明細など）は外部キー違反で全体が取り消されるので、先にそちらを削除してください。
- **列の制限:** 自動採番（IDENTITY）・計算列・バイナリ列は編集できません（列名に 🔒）。🔑 は主キー、* は必須の列です。
- **列の追加:** 列の追加や削除はできません（行の追加・更新・削除のみ）。
- **分析画面への反映:** 分析で使っているテーブル（物件情報・査定/修正単価・標準単価など）を保存したら、「今すぐ再読込」で検索・分析画面に反映してください。
- **一覧の表示:** 一覧は 200 行ずつ表示します。検索欄は全列の部分一致で、見出しのクリックで並べ替えます。

## Stencile変換（ヘッダーの「🧰 Stencile変換」→ 別ウィンドウ）

Stencile（元データ Excel）から **① 物件諸情報** と **② 査定・修正単価** を取り出し、内容を確認してから **DB に登録**（または Excel に保存）します。
旧 Python ツール（`Stencile変換ツール/` の ①②）を移植・整理したものです。③ DB編集は、メイン画面の「🗄 DB編集」にまとめました。

1. **元データを選ぶ**: Stencile フォルダ（サブフォルダ込み可）、処理する内容（①②）、マッピング YAML、②の単価テンプレート
   - マッピング YAML は未指定なら、元データフォルダ内の `*mapping*` / `*マッピング*` → 同梱の既定マッピング（`Stencil/Assets`）の順に自動で使います
   - 前回の指定は記憶します
2. **読み込んで確認**: 進捗とログ（[STEP]/[FILE]/[OK]/[WARN]/[ERROR]）を見ながら読み込み、一覧で確認します
   - 状態: 新規 ／ 既存あり（DB に同じ project_id がある）／ 警告 ／ エラー。行をクリックすると右に詳細
   - **新規は最初から選択、既存ありは未選択**。既存ありをチェックすると「上書き」になります
3. **DB登録・Excel保存**
   - DB登録: ① 物件情報は新規 INSERT／既存 UPDATE、② 単価はその物件の既存行を削除して入れ替え（SqlBulkCopy で一括）。**全体を1トランザクション**で行い、失敗したらすべて取り消します
   - 型に合わない値（数値列に「有」など）は空欄で登録し、ログに警告を出します
   - Excel保存: `物件諸情報一覧.xlsx`（62列）と `単価テーブル_集約結果.xlsx`（査定・修正の2シート）。Python 版と同じ構成です
   - 登録するとメイン画面に「再読込」の案内が出ます

Python 版から直した点:

- 「1SLDK」の戸数が常に 0 になっていた不具合を修正
- テンプレートの行数（373行）・積算予算の行範囲（2〜938行）を固定せず、空行まで／最終行まで読む
- 同梱マッピングの誤記（`構成比_板金工事_修正予算: PJ28` → `P28`）を修正
- Excel を開いたままでも読める（共有モードで読込）

## DB編集の Excel取込（「📥 Excel取込」）

開いているテーブルに Excel の表を取り込みます。1行目を見出しとして、DB の各列にどの見出しを入れるかを選びます（同じ名前・英字部分・日本語部分が一致する見出しは自動で対応付け）。
取り込んだ行は表に「追加」（緑）として入るので、確認してから「💾 保存」で DB に反映します（失敗したら全体を取り消し、Ctrl+Z で取込自体を取り消し）。

## 変更履歴と取り消し（DB編集の「📜 変更履歴」）

このアプリから DB を変更すると（DB編集の保存・Excel取込・Stencile登録・関連行の一括削除）、**いつ・だれが（Windows ユーザー／PC名／DBログイン）・どのテーブルのどの行を・どう変えたか**を、変更と同じトランザクションで同じ DB に記録します（記録に失敗したら変更自体も取り消し）。

- 記録先: `ChangeBatch_変更操作`（1回の保存＝1操作）と `ChangeRow_変更明細`（行ごとの変更前／変更後を JSON で保存）。テーブル名は設定画面で変更可
- テーブルは初回の保存時に自動作成。CREATE TABLE の権限が無い場合は、管理者が `sql\ChangeLog_変更履歴.sql` を実行
- 履歴画面: 期間・ユーザー・テーブル・キーワード（値の中身も検索）で絞り込み → 操作を選ぶと「列: 変更前 → 変更後」が表示
- **↶ この操作を取り消す**: その操作だけを元に戻す（追加→削除、更新→元の値、削除→再追加）
- **⏪ この時点まで戻す**: その操作以降のすべての操作を新しい順に取り消す
- 取り消し後に別の変更が入っていた行は「衝突」として表示し、**何も変更しません**。内容を確認して「⚠ 強制的に戻す」を押すと上書きします
- 取り消し自体も「取り消し」操作として記録されるので、取り消しを取り消すこともできます
- 履歴は無期限に残ります。「🗑 古い履歴を削除」で指定日数より前の履歴を手動で削除できます（削除した操作は取り消せなくなります）

注意:
- SSMS など**アプリ以外からの変更は記録されません**
- トリガーが有効なテーブルでは `OUTPUT` 句が使えず保存がエラーになります（その場合はご相談ください）
- バイナリ列（画像など）は戻せません
- 削除した行を同じ ID で戻すには IDENTITY_INSERT（ALTER 権限）が必要です。権限が無い場合は新しい ID で再追加し、警告を表示します

## Python 版との違い

意図的に変えた点:

1. **物件一覧にも面積レンジを適用**（Python 版は統計と一覧で件数がずれていた）
2. **地域の選択肢を連動**し、**各選択肢に件数を表示**
3. **グラフは指標タブで1つずつ大きく表示**し、各物件の点を重ねてクリックできるようにした
4. **接続先・モデルを画面から設定・保存**（Python 版は定数・環境変数）
5. 階数の選択肢を `7.0` ではなく `7` と表示。地下階数「地下1階」を地上階数と取り違えないようにした
6. 物件のSELECTで同じ別名 `ALC` が2つあったため、トラック台数側を `ALC車両` に改名
7. 選択中の物件は、条件変更後も一覧に残っていれば選択を維持する

あえて変えていない点（要確認）:

- **鉄筋歩掛**は Python 版と同じく `鉄筋（Kg/m2）` 列の値をそのまま t として割っています（kg→t 換算はコメントアウトされたまま）。
  直す場合は `Services/LaborRateService_型枠鉄筋歩掛.cs` のコメント箇所を修正してください。
- 判断サマリー・確認観点・物件説明は Python 版と同じく**ルールベース**です（LLM を使うのは「AI 条件設定」だけ）。

## 見積AI-OCR（ヘッダー・ホームの「🧾 AI-OCR」→ 別ウィンドウ）

`Estimate_OCR_GUI_v6_OCR行監査・参考明細対応`（Python 版）を C# に移したものです。協力業者の見積PDFを Azure AI Document Intelligence（prebuilt-layout）で読み取り、明細を構造化した Excel・JSON にします。

1. 「⚙ Azure設定」でエンドポイントとキーを入れて「接続テスト」→「保存」（キーは DPAPI で暗号化して保存。空欄なら Python 版と同じ環境変数 `DI_ENDPOINT` / `DI_KEY` を使います）
2. 「＋ PDFを追加」（複数可。ページ数を表示）→ 保存先 → 構造化ルール（共通ルールは同梱。協力業者差分ルールは任意）
3. 「▶ OCR・構造化を実行」→ 2ページずつ Azure に送り、全ページを統合 → 構造化。途中で「■ 中止」もできます
4. 結果の一覧で PDF を選ぶと、構造化明細 / 要確認だけ / OCR行監査 を画面で確認できます。「📊 構造化Excel」「📂 フォルダ」で開けます

出力は Python 版と同じ構成です（PDF ごとに `PDF名_日時` フォルダ → `01_OCR抽出`（統合 JSON・OCR 確認 Excel）/ `02_構造化`（構造化明細・集計・確認・OCR行監査の3シート））。
ルールを直したときは「📄 OCR済みJSONから構造化だけやり直す」で、**Azure を使わずに**（＝処理枚数を増やさずに）作り直せます。

### 処理枚数（無料枠の目安）

- ヘッダーのメーターに「本日の処理枚数 / 上限」を表示します（ホームのアイコンにも表示）。数えるのは **Azure が解析したページ数** です（失敗した送信は数えません）
- 既定は上限 **500 枚/日**。**300 枚を超えると黄色**、**400 枚を超えると赤**、500 枚に達すると赤く点滅し、画面上部に注意を出します
- 実行前に「実行後の見込み」を表示し、上限を超える場合は確認します
- 上限・色を変える枚数・数える期間（1日 / 1か月）は「⚙ Azure設定」で変更できます
- 記録は `%AppData%\SimilaritySearchApp\ocr_usage.json`（日ごと、90 日分）。アプリを閉じても残ります

## AIアシスタント（検索・分析の右側のチャット）

ローカルLLM（Ollama）が会話の流れから対応を判断します。

- 挨拶・お礼・使い方の質問・「いまの中央値は？」のような結果についての質問 → 会話で答えます（データ読込前でも会話できます）
- 「東京都のRC造7階で内装工事」「S造にして」など絞込みの依頼 → 条件を設定して結果を更新します
- 「まとめて」「確認すべき点は？」「この物件は？」→ 判断サマリー／確認観点／選択物件の説明
- 直近 12 発言を覚えているので、「じゃあ神奈川県だと？」のような続けての依頼もできます。「クリア」で会話の記憶も消えます
- 数値は画面の状況（件数・中央値など）として渡したものだけを使うよう指示しています（作り話をしない）
- 「タイルの標準単価は？」「内装工事の協力業者は？」のように、画面に無い情報は **DB のテーブルを調べて** 答えます（データ読込前でも可）
  1. AI がテーブル一覧（列名つき）から、調べるテーブル・キーワード・列を選ぶ
  2. アプリが **読み取り専用の検索（SELECT のみ・最大 50 行）** を実行（AI に SQL は書かせず、テーブル・列は実在するものだけ。全角/半角カナの表記ゆれも探す）
  3. 検索結果だけを根拠に AI が答え、「📋 参照」と「🗄 DB編集で開く」ボタン（検索語を入れた状態で開く）を表示
  - 変更履歴のテーブルは対象外です。どのテーブルを選ぶかは AI の判断なので、意図と違うときは「建築材料マスタで」のようにテーブルを指定してください

コンテキスト長（設定 → ローカルLLM の num_ctx、既定 8192）が足りないとエラーになるため、その場合は大きくしてください。

## 見積DB連携（AI-OCR 画面 → 確認・取決めウィンドウ）

AI-OCR の結果を DB に保存し、物件・業者の紐づけ、明細の確認、取決め総額からの掛率計算・確定までを行います。
仕様・進捗は `docs/2026-10-13_OCR見積DB連携/`（[実装計画_APP01-03.md](docs/2026-10-13_OCR見積DB連携/実装計画_APP01-03.md)）を参照。DB の表は同フォルダの構造SQLで作成済みのものを使い、アプリからは DDL を実行しません。

| AI-OCR 画面のボタン | 動作 |
|---|---|
| 📋 内容確認・取決め確定（明細欄） | 選択中の構造化済み結果を DB に取り込み（登録済みならそのまま）、確認・取決めウィンドウを開く。OCR した元PDFも一緒に保存 |
| 📥 既存OCR結果を取り込む | 構造化JSON（同じフォルダの構造化Excel・統合OCR JSON は自動検出）と任意の元PDF を取り込む。Azure は使わない |
| 🗂 保存済み見積を開く | DB の見積一覧（再起動後・別PCでも同じ内容） |

確認・取決めウィンドウ（AI-OCR ウィンドウを Owner にした別ウィンドウ）:

1. **紐づけ**：物件（現場コード・住所）と業者（取引先CD・住所）を候補から選んで保存。候補が 1 件でも自動では決めません（同名の業者は別々の候補として出ます）
2. **明細・要確認・行監査**：行を選ぶと右の元PDFが該当ページへ移動。人の確認（未確認／確認済／計算対象外）と補正値（数量・単位・単価・金額）を保存。OCR の原値は変わりません
3. **取決め**：基準総額（表紙金額／明細合計／確認入力）・税区分・取決め総額・根拠ページ → 計算プレビュー → 確定
   - 掛率＝取決め総額÷基準総額（小数12桁）、取決め換算単価＝単価×掛率（10円単位。例: 1,071.98 → 1,070）、換算金額＝金額×掛率（円）。四捨五入（0 から遠い側）。残差は配賦せず保存
   - 確定には、紐づけ・元PDF・根拠ページ・税区分・要確認行の確認・残差や増額の理由などが必要（足りないものを一覧で表示）
   - 確定済みの版は変更できません。「新しい版で訂正」で次の版の下書きを作り、確定すると前の版は「旧版」になります（履歴タブで閲覧）
4. 資料（PDF・Excel）は DB から一時フォルダに取り出して表示します（Excel を編集しても DB には反映されません）
5. **諸経費**（「内訳合計＋諸経費＝総合計」の見積）：取決めタブの「⓪ 諸経費」で、明細の「諸経費」などの行を選ぶか金額を手入力します。諸経費を各明細の単価へ配分してから掛率をかけます
   - 諸経費掛率 ＝ (内訳合計＋諸経費) ÷ 内訳合計、換算単価 ＝ 単価 × 諸経費掛率 × 掛率（途中では丸めず最後に 1 回）
   - 画面には「諸経費込み単価」と「取決め換算単価」の両方を表示します。DB に列の追加が必要です（`docs/2026-10-13_OCR見積DB連携/OCR見積取決め_諸経費列追加.sql`）
6. **見積の削除**：ヘッダーの「🗑 この見積を削除」で、明細・行監査・取決め・資料・取込記録をまとめて削除します。確定済みの取決めがある見積は、見積ID の入力と理由が必要です。削除は「📜 変更履歴」に記録されますが、資料（PDF・Excel）の本体は戻せません
7. **物件・業者の候補**：候補をクリックすると、入力欄と「選択中」の欄にすぐ入ります（「紐づけを保存」で確定）

DB編集で物件情報の行を削除するとき、その物件に見積DB の見積が紐づいていれば削除を止めます（取決めの履歴を連鎖削除しないため）。先に見積を削除するか、紐づけを外してください。

安全面：取込・確定は 1 トランザクション。実DBの列の型・長さ・小数桁に収まらない値は丸めず・切り詰めず、どの行のどの列かを表示して止めます。確定は確定要求キーで二重クリック・再送を 1 回にまとめ、rowversion で同時編集を検出します。確定者・確認者は Windows のユーザー名で記録します。
