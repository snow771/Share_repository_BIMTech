## 概要

建築積算・コストマネジメント業務において、複数の「Stencile（元データ Excel）」から
**物件諸情報の変換集約・査定/修正単価の集約・コストデータベース編集** を統合的に行うデスクトップ GUI ツール。

Python（Tkinter）ベースの統合ランチャー（`launcher.py`）から 3 つのツールを管理・起動する。

## セットアップ

### 1. ファイルの配置

以下のファイルをすべて同一フォルダに配置してください。

```
project_root/
├── launcher.py                          ← これを起動
├── stencilデータ変換_完成版.py
├── stencile単価集約ツール.py
├── 20260127_mapping_最新版.yaml
├── requirements.txt
└── modules/
    └── db_editor/
        ├── __init__.py
        ├── db_editor.py
        ├── db_connection.py
        ├── grid_panel.py
        ├── er_panel.py
        └── dialogs.py
```

### 2. 依存パッケージのインストール

```bash
pip install -r requirements.txt
```

**requirements.txt の内容：**

```txt
# ① ② 用
openpyxl>=3.1.0
PyYAML>=6.0

# ③ DBエディタ用
pandas>=2.0.0
pyodbc>=5.0.0
```

### 3. ODBC ドライバーの確認（③ のみ必要）

SQL Server への接続に `ODBC Driver 17 for SQL Server` または
`ODBC Driver 18 for SQL Server` が必要です。

インストール確認コマンド：

```python
import pyodbc
print([d for d in pyodbc.drivers() if "SQL Server" in d])
```

何も表示されない場合は、Microsoft 公式サイトから
「Microsoft ODBC Driver for SQL Server」をインストールしてください。

### 4. ランチャーの起動

```bash
python launcher.py
```

## 基本的な使い方

### ① 物件諸情報変換を実行する

1. ランチャーの **「① Stencile 情報変換」** カードで **▶ 起動する** を押す
2. **元データ Excel が入ったフォルダ** を選択する
3. **mapping YAML** を選択する（スクリプトと同フォルダにあれば自動検出）
4. **出力ファイル名** を指定する（初期値：`物件諸情報一覧.xlsx`）
5. ログエリアに `[DONE]` が表示されたら完了。指定した場所に Excel が生成される

### ② 査定・修正単価集約を実行する

1. ランチャーの **「② 査定・修正 単価マスタ作成」** カードで **▶ 起動する** を押す
2. **テンプレートファイル**（`〇〇期RC造_〇〇単価.xlsx`）を選択する
3. **元データ Excel が入ったフォルダ** を選択する
4. **出力先フォルダ** を選択する
5. ログエリアに `[DONE]` が表示されたら完了。`単価テーブル_集約結果.xlsx` が生成される

### ③ コストデータベース編集を使う

#### 起動・接続

1. ランチャーの **「③ コストデータベース編集」** カードで **▶ 起動する** を押す
2. DB エディタウィンドウが開き、接続ダイアログが表示される
3. サーバー名を確認（初期値：`localhost\sqlexpress`）し、接続するデータベースを選択する
4. 接続に成功すると、左列にテーブル一覧が表示され、右側に ER 図が描画される

#### データの閲覧・編集

| 操作 | 手順 |
|---|---|
| テーブルを開く | 左のテーブル一覧から選択、または ER 図のノードをダブルクリック |
| 値を編集する | グリッドのセルをダブルクリック → 値を入力 → Enter |
| 行を追加する | ツールバー **「＋ 行」** → 各列の値を入力 → 追加 |
| 行を削除する | 削除したい行を選択 → **「－ 行」** |
| 列を追加する | **「＋ 列」** → 列名・データ型・NULL 可否を入力 |
| 列を削除する | **「－ 列」** → 削除対象列を選択 |
| データを絞り込む | 検索バーにキーワードを入力 → リアルタイムでフィルタ |

> **すべての変更操作（更新・追加・削除）は確認ダイアログ（Yes / No）を経由してから確定されます。**

#### PK / FK 制約管理

1. テーブルを選択した状態でツールバー **「🔑 制約」** を押す
2. `制約管理ダイアログ` が開く

| 操作 | 方法 |
|---|---|
| 主キー（PK）を設定 | PK にする列のチェックボックスをオンにして「確定」 |
| 複合主キーを設定 | 複数の列を同時にチェックして「確定」 |
| 主キーを削除 | すべてのチェックをオフにして「確定」 |
| 外部キー（FK）を追加 | FK セクション「FK を追加」→ 自列・参照テーブル・参照列を選択 |
| 外部キーを削除 | FK 一覧の「削除」ボタンを押す |

> 制約の変更確定後、**ER 図が自動的に再描画** され、最新のリレーション状態が反映されます。

#### Excel コピー＆ペースト

| 操作 | 方法 |
|---|---|
| グリッドからコピー | 行を選択 → **Ctrl+C** でタブ区切りテキストをクリップボードへ |
| Excel からペースト | Excel でセルをコピー → グリッドの貼り付け先セルを左クリック → **Ctrl+V** |

**ペースト時の動作：**
- 左クリックしたセルを起点に、右方向・下方向へ値が入る
- **PK 列は自動的にスキップ**される（書き換えが許可されない）
- テーブルの行数・列数を超える部分は自動でスキップされる
- `ペースト確認ダイアログ` で対象セル数・スキップ数を確認してから実行する

#### Excel ファイルのインポート

1. テーブルを選択した状態でツールバー **「📥 Excel取込」** を押す
2. 取り込む Excel ファイル（`.xlsx` / `.xlsm`）を選択する
3. `Excel インポートダイアログ` が開く

| 項目 | 内容 |
|---|---|
| 列マッピング | Excel 1 行目のヘッダーと DB 列名が一致すれば自動マッピング |
| 手動マッピング | 不一致の場合はコンボボックスで手動対応付け |
| 除外 | 「(未使用)」を選択した DB 列は取込対象外 |
| プレビュー | Excel の先頭 5 行をダイアログ内で確認できる |

**取込時の動作：**
- 1 行でも INSERT に失敗した場合は全件ロールバックされる
- 最終確認ダイアログで件数を確認してから実行する

#### ER 図パネル

| 操作 | 動作 |
|---|---|
| テーブルノードをクリック | そのテーブルをグリッドに読み込む |
| テーブルノードをダブルクリック | グリッドにそのテーブルを読み込む |
| テーブルノードをドラッグ | 配置を移動できる（次回起動時も保持）|
| グリッドの列ヘッダーをクリック | その列に関係する FK リレーション線が強調表示される |
| マウスホイール | ER 図のズームイン / ズームアウト |
| 🔍＋ / 🔍－ ボタン | ズーム操作 |
| ↺ リセット | テーブルノードを初期配置に戻す |

**リレーション線の見方：**

| 線のスタイル | 意味 |
|---|---|
| グレー細線 + 矢印 | FK によるリレーション（参照元 → 参照先） |
| アクセントブルー太線 | 現在グリッドで選択中の列が絡むリレーション |
| 線なし | FK 制約が未定義のテーブル（独立ノードとして表示）|

### ログの見方（ランチャー）

| 表示色 | タグ | 意味 |
|---|---|---|
| 青 | `[STEP]` / `[DIALOG]` | 処理ステップの進行・ダイアログ操作待ち |
| 緑 | `[OK]` / `[DONE]` | 各ステップの正常完了・全処理完了 |
| 白 | `[FILE]` | ファイル処理中 |
| 黄 | `[WARN]` | スキップ・警告 |
| 赤 | `[ERROR]` | エラー発生 |

## トラブルシュート

| 症状 | 原因候補 | 対応 |
|---|---|---|
| ランチャーが起動しない | Python 未インストール・依存ライブラリ不足 | Python 3.10 以上を確認し `pip install -r requirements.txt` を再実行 |
| `ModuleNotFoundError: yaml` | PyYAML 未インストール | `pip install PyYAML` を実行 |
| mapping YAML が自動検出されない | ファイル名・配置場所が条件に合っていない | スクリプトと同フォルダ・元データフォルダ・カレントディレクトリのいずれかに配置し、ファイル名に `mapping` または `マッピング` を含める |
| 出力 Excel を保存できない | 同名ファイルを Excel で開いたまま | ファイルを閉じてから再実行 |
| 単価がすべて 0 になる | 工種コードがテンプレートと一致していない | 元データとテンプレートの工種コードを照合する |
| ③ DB に接続できない | SQL Server 未起動 | SQL Server Express サービスが起動していることを確認する |
| ③ DB に接続できない | ODBC Driver 未インストール | `pip install pyodbc` 後、Microsoft ODBC Driver for SQL Server をインストールする |
| ③ DB に接続できない | 権限不足 | 実行ユーザーが対象 DB に対する参照・更新権限を持っているか確認する |
| ③ ER 図にリレーション線が出ない | FK 制約が DB に未定義 | 「🔑 制約」ダイアログから FK を追加するか、DB 側に制約を定義する |
| ③ ペーストしても反映されない | クリップボードの内容がタブ区切りでない | Excel でコピーした内容のみ対応。他アプリからのコピーは非対応 |
| ③ Excel 取込で型エラー | Excel 側の値が DB 列のデータ型と不一致 | Excel の値を確認し、型に合った値に修正する（例：数値列に文字列が混入していないか）|
| ③ PK/FK 変更でエラー | 既存データが制約条件を違反している | 元データを修正してから制約を設定する（例：重複値がある列は PK にできない）|

## データ保護に関する注意

- 本ツールは物件情報・単価情報・コストデータを扱います。共有フォルダや外部環境に配置する場合は、社内ルールに従いアクセス権限を設定してください。
- **③ DB エディタを使用する前に、対象 DB のバックアップを取得することを強く推奨します。**
- 本番 DB に接続する場合は、事前に検証環境で動作確認してください。
- 編集・削除操作はすべて確認ダイアログ経由で実行されますが、**確定後の UNDO 機能はありません**。
- PK/FK 制約の追加・削除は既存データに影響する可能性があります。操作前に必ずデータの整合性を確認してください。

## 機能仕様

### ランチャー（`launcher.py` v1.2）

ダークテーマの Tkinter GUI で、3 つのツールをカード型 UI で管理・起動する。

**動作方式：**

- 各ツールはサブプロセス（`subprocess.Popen`）として起動
- 一時ラッパースクリプト（`stencile_tmp_*.py`）を Temp フォルダに生成し、標準出力をリアルタイムでログ表示
- 終了時に一時ファイルを自動削除

**カラーパレット：**

| 用途 | カラー |
|---|---|
| 背景 | `#0f1117` |
| ① アクセント | `#4f8ef7`（ブルー）|
| ② アクセント | `#00c9a7`（ティール）|
| ③ アクセント | `#a78bfa`（パープル）|
| 成功 | `#22c55e` |
| エラー | `#ef4444` |
| 警告 | `#f59e0b` |

---

### ① 物件諸情報変換（`stencilデータ変換_完成版.py`）

**処理フロー：**

```
[1] フォルダ選択 → [2] mapping YAML 自動検出 or 手動選択
→ [3] 出力ファイル名指定 → [4] 各 Excel からデータ抽出
→ [5] project_id・物件名でソート → [6] 書式付き Excel 出力
```

**必須シート（元データ Excel 側）：**

| シート名 | 取得内容 |
|---|---|
| `実行予算表書` | 主要物件情報（請負金額・面積・間取など）|
| `実行予算・引継書` | 山留・杭・土工事など工法情報 |
| `原価推移表` | 形態・ELV 情報 |

**出力列（62列）：**

`project_id`・`物件名`・`現場住所_都道府県/市区町村/町名`・`請負金額`・`契約時予定利益`・`利益率`・各面積（敷地/建築/法廷/施工）・`施工坪単価`・`工期`・`構造`・`階数`・間取（1R〜3SLDK）・用途・`世帯数`・`形態`・`ELV`・仕様・工法・`生コン車`・`ポンプ車`

**出力書式：**

| 設定 | 内容 |
|---|---|
| ヘッダー | 水色塗り（`ADD8E6`）・游ゴシック 11pt Bold・中央揃え |
| 数値書式 | 請負金額・利益 → `#,##0`、面積・坪単価 → `#,##0.0` |
| ペイン固定 | AT2（46列目・2行目）|

---

### ② 査定・修正単価マスタ作成（`stencile単価集約ツール.py`）

**処理フロー：**

```
[1] テンプレートファイル選択 → [2] 元ファイルフォルダ選択 → [3] 出力先フォルダ選択
→ [4] シート「単価テーブル_査定」生成（E列 = 査定単価）
→ [5] シート「単価テーブル_修正」生成（F列 = 修正単価）
→ [6] 元テンプレートシートを削除して保存
```

**元データ Excel の参照セル：**

| シート | セル | 取得内容 |
|---|---|---|
| `実行予算表書` | `C1` | `project_id` |
| `積算予算` | `D列`（2〜938行） | 工種コード |
| `積算予算` | `E列`（2〜938行） | 査定単価 |
| `積算予算` | `F列`（2〜938行） | 修正単価 |

**出力ファイル：** `単価テーブル_集約結果.xlsx`（出力先フォルダに保存）

#### グリッドのツールバーボタン一覧

| キー | 操作 |

#### 確認ダイアログ一覧

| 操作 | ダイアログ種別 | 特記事項 |
|---|---|---|
| セル値の更新 | `ConfirmDialog`（通常）| 変更前・変更後の値を表示 |

| 行の削除 | `ConfirmDialog`（⚠ 赤系）| 削除件数を表示 |
| 列の追加 | `ConfirmDialog`（通常）| 列名・型・NULL 可否を表示 |
| 列の削除 | `ConfirmDialog`（⚠ 赤系）| データ喪失の警告を表示 |
| 制約変更（PK/FK）| `ConfirmDialog`（⚠ 赤系）| 変更内容の一覧を表示 |

## 既知の注意事項・制約

| 項目 | 内容 |
|---|---|
| WMF 警告 | openpyxl の WMF 画像警告はランチャー側で自動抑制済み（処理に影響なし）|
| 一時ファイル | ランチャーは子プロセス起動のため Temp フォルダに `stencile_tmp_*.py` を生成し、処理後に自動削除 |
| ① YAML 自動検出 | スクリプト同フォルダ・元データフォルダ・カレントディレクトリを検索。`mapping` または `マッピング` を含むファイルを優先 |
| ② 行数固定 | テンプレートの工種コードは 373 レコード（2〜374行）固定前提。テンプレート変更時は `process_excel_file()` の range を要確認 |
| ③ UNDO 非対応 | 確認ダイアログ経由でのみ確定。取り消し（UNDO）機能は未実装 |
| ③ 列移動 | 列の表示順変更は未実装。`displaycolumns` オプションで追加可能 |
| ③ FK 未定義テーブル | 外部キー制約が DB に未定義のテーブルはリレーション線なしの独立ノードとして表示 |
| ③ 多数テーブル | テーブル数が多い場合（目安：20 以上）はノードが密集するため、ズーム縮小またはノード移動で対応 |
| ③ ER 図レイアウト | 配置は `er_layout.json` に保存。接続 DB を変更した際は「↺ リセット」または手動でファイルを削除 |
| ③ FK 複合列 | 現在の実装は 1 列対 1 列の FK のみ対応（複合列 FK は未対応）|
| ③ ペースト起点 | ペーストは最後に**左クリックしたセル**を起点とする。ペースト前に必ず起点セルをクリックして確認すること |
| ③ スキーマ推定 | ER 図ノードのダブルクリックによるテーブル選択は `dbo` スキーマを仮定。複数スキーマ環境では要拡張 |
